## Rollback baseline

The certified rollback reference is the production application commit:

`ad936db77c18a0fca942a3cc405978344c5db9ca`

If a post-release regression occurs:

1. Freeze further production changes.
2. Capture the active Vercel and Railway deployment identifiers.
3. Revert or redeploy the certified production application commit.
4. Verify homepage, API health, authentication, Chat, RAG, and contact delivery.
5. Record the incident and recovery evidence before resuming feature deployment.

## Known non-blocking backlog

- Genesis isolated Railway staging and authenticated acceptance
- PRIMETIME governed API/UI/tenant acceptance

## Release decision

**GO**

The critical production user paths and core infrastructure dependencies were validated on the certified baseline. New feature work should branch from the frozen v1.0.0 baseline and must not bypass normal CI, review, staging, or rollback controls.
